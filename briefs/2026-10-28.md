# Run brief — 2026-10-28

The strongest idea today is **make authority narrower before making automation larger**. We looked across cloud Git storage, background coding-agent identity, AI-assisted command approvals and Java TLS. At first these look unrelated. Each hides an important distinction between what a system *can* do and what it has actually been authorized to do or proven to have done. The most useful engineering improvements are not another chatbot worker; they are an installation identity that survives a departing engineer, a write lock that covers just one mutable reference, and a TLS canary that proves which cryptographic group was actually negotiated.

**GitHub Copilot SDK now has a workload-owned identity path** (October 27, public preview). An organization-installed GitHub App can request inference using a one-hour installation token and bill the organization, with the organization controlling model selection and spending. GitHub Actions in organization-owned repos can instead use `GITHUB_TOKEN` and `copilot-requests: write`. The important operational subtlety: the external App's organization permission is named **Read-only**, but that *does not prevent spending*. Copilot inference identity also does not authorize pushing or merging code. For a real background coding agent, the right structure is: org-owned inference credential, isolated worktree, separately authorized PR publisher and independent required checks. This preview is organization-scoped, not a magic new login mode for all personal GitHub repos.

**Permission automation has a smaller role than authorization.** GitHub Copilot's Assisted permissions became generally available on October 26. A model now classifies some eligible tool requests as clearly safe and passes others to a human. That is useful UX and may improve unattended completion—but it doesn't justify moving authority over production deployments, secret reads or protected merges into a model's classification. We updated the existing enforcement-bound approval recipe accordingly. A useful experiment would quantify how many prompts Assisted removes *without* creating false approvals, while deterministic deny rules and the executor remain the final authority.

The GitHub storage case study (October 21) provides a different scaling lesson: **serialize only writes that actually contend on the same value**. GitHub's earlier global repository lock combined with a remote replica's network latency limited the hottest repositories. A ref-scoped quorum admits independent branch pushes concurrently; GitHub reports roughly 3–4× throughput in its own tests. A virtual write replica makes object storage durable before success, while read replicas scale independently at the cost of explicit freshness management. For our systems, we can prototype a simpler Postgres CAS + immutable-object service and test what happens under 100 separate agent refs versus one shared `main` ref. The latter remains a bottleneck even in an ideal per-key design.

The non-agent addition is immediately practical for JVM/platform work. JDK 27 now offers **hybrid post-quantum TLS 1.3** key exchange by default through JSSE: `X25519MLKEM768` alongside classical fallback. That only protects the key agreement when the *peer negotiates it*; native TLS libraries, middleboxes, proxies and custom named-group overrides can change the picture. The knowledgebase now includes a concrete service matrix, JSSE debug/config snippets, TLS-leg inventory and measured rollout/rollback plan. It is a good example of the kind of verification we also want in agent work: report observed postconditions, not hopeful configuration.
