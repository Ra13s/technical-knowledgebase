# Run brief — 2026-11-25

Today the useful distinction is between partial success and an actual working product. JoyFrontBench's average task score (87.69%) and whole-application success (51.52%) differ sharply in one tested harness. Tests-as-data makes the practical response easier: put human-reviewable business expectations in protected fixtures and verify the same candidate artifact with an independent runner. This is especially helpful for multi-step UI workflows, where individually passing checks can conceal a broken user journey. Keep mutation checks as a separate measure of defect detection.

For Java coding agents, Dukehoff exposes compiler-aware NetBeans operations over MCP: usages, rename, signature changes and structural migrations. This supplements graph search when the exact type or overload matters. Its own evaluation suggests useful potential, not a general productivity guarantee; compare on our real projects.

For everyday Java CI, Surefire/Failsafe 3.6+ has an especially practical extension: capture jstack before killing a hung test fork. Set the inner timeout below the outer CI deadline, preserve the artifact and use a bounded watchdog for other runners. A rerun is not a substitute for the original blocked state.

The best next experiment is to protect a small set of user journeys and seed known failures, then measure complete journey success and false acceptance instead of counting green individual checks.
