# Run brief — 2026-10-04

The main idea from this run is **keep the thing that must remain trustworthy outside the component whose behavior is allowed to vary**. Replit is increasingly letting the core model decide when to delegate, which specialist to use and how much effort to spend, while the harness still defines the available primitives. Uber's MCP architecture similarly separates broad discovery from actual enablement. The architectural bias is becoming clear: let models choose strategy inside a bounded system rather than encoding every decision in prompts.

The Java performance finding is the cleanest version of the same idea. If a latency benchmark schedules requests inside the same JVM as the application, a GC pause can stop both the application and the benchmark driver. The test then fails to create some arrivals that would have existed in reality, making tail latency look too optimistic. A recent SPECjbb2015 experiment found roughly 2-3x p99 differences for collectors with non-trivial pauses when comparing colocated and separated setups. The KB now says: for GC/safepoint-sensitive p99 work, put request scheduling in another JVM and correlate intended arrivals with pause telemetry.

Kubernetes 1.37 Memory QoS also passed the admission test. The non-obvious part is that the Beta feature gate is enabled by default, but that **does not activate throttling or tiered reservation**. The default kubelet configuration leaves memoryThrottlingFactor unset and memoryReservationPolicy at None. We now have a focused recipe for opting into memory.high and/or memory.min/memory.low behavior on a canary node pool and measuring the effect before broad rollout.

On the agent side, Uber's strongest contribution is production-scale evidence for progressive discovery. Uber reports more than 800 MCP servers and 5,000 tools, with automatic discovery but disabled-by-default exposure and owner review. That strongly reinforces our existing tool-search and MCP guidance without needing another near-duplicate canonical page.

Replit's current harness work is useful pressure on our existing ablation thinking. Their harness exposes specialists, tiers and effort choices while a capable model decides how to compose them. The vendor benchmark favors that composable setup over a single-worker comparison. The reusable idea is the experiment: when the primary model changes, test whether a fixed router still earns its complexity.

A source-level study of eleven coding harnesses points in the same direction: production harnesses increasingly look like explicit platforms with separable loop, model integration, tools, context, orchestration and extension subsystems. Combined with this run's other findings, the useful rule is: **give the model flexible strategy, but keep platform behavior and measurement independently testable**.

## What I would try next

The cheapest high-value experiment is the JVM one: compare a colocated versus separate request scheduler around measurable GC pauses. For agent work, freeze 30-50 real tasks and compare fixed routing against model-directed specialist selection; if the router no longer buys quality, delete complexity rather than admiring it like a vintage chandelier.
