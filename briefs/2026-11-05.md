# Run brief — 2026-11-05

Three systems we found this time—an autonomous PR creator, a cross-service search index and client-to-backend tracing—converge on a useful engineering rule: **give each contributing component a stable identity and a narrow contract; make a separate system responsible for assembling, validating and publishing the result**. This is different from piling more intelligence into one orchestrator. A single agent session, search service or HTTP trace is not the right unit for every real workflow.

The best agent case study is from **Inkitt Tech** (published August 26; resurfaced by InfoQ November 4). Their one-shot PR workflow is not a static list of prompts. It runs an authenticated, deduplicated event loop whose pure `(run state, event) -> next action` function has no model or network dependencies. Each model stage is an ephemeral container; the orchestrator keeps external credentials and performs PR/notification side effects. The run row and conditional database writes allow recovery after a crash and prevent duplicate webhooks from launching duplicate stages. Verification, CI repair and conflict resolution each have two attempts; a real Git diff determines if restricted paths changed. Importantly, CI job webhooks are treated as hints to query the entire check suite for the exact head SHA. The system stops at a **draft PR and human gate**, and Inkitt reports daily shipping but no audited success rate. This strengthens our existing durable-agent architecture with a reducer we can actually unit-test and fault-inject.

An equally reusable but different case is **Uber Freight's composable search** (October 27). Rather than letting one microservice own a sprawling search document assembled from many upstream services, each team declares a field-owned fragment. The search platform uses the same transformation in batch bootstrap and CDC live updates, handles linked-entity denormalization and one-to-many folding, generates index mappings and continuously checks source/index parity. Uber reports 70+ source topics, 300 fragments and 20+ indices, with few-second freshness, but those production numbers are not a causal benchmark. The practical experiment is to build a three-source index where deleting a child, changing a linked customer and replaying out-of-order CDC all converge to the correct document without overwriting other owners' fields.

**LinkedIn's OpenTelemetry journey tracing** (October 22) gives a third manifestation of correct identity. One screen can launch three server requests, and each deserves its own `traceId`. LinkedIn adds a `pageForestId` above them, allowing a developer to select a member-facing experience and drill into all related request traces. Coordinated head sampling keeps frontend and backend from discarding different halves; mobile exporters use bounded batches and best-effort background flush. It is an unusually precise recipe for linking a failed UI action to the backend timeout that caused it, and a reminder that sampling, PII safeguards and storage cost are part of the architecture rather than afterthoughts.

Two existing entries also improved. **Uber's MCP Gateway** (October 1, publicized by InfoQ November 2) automatically crawls IDLs and native MCP manifests but keeps newly discovered tools **disabled pending service-owner approval**. It then offers incremental tool/schema discovery or an agent CLI instead of injecting 5,000 tools into context. **Google PageBreak** (September 24, reported October 31) demonstrates why an agent's security finding should reach a product team only after an *independently authored* validator reproduces it; failed or unavailable validation becomes an internal research item, not proof of safety. The direct design lesson across all these sources is the same: **discovery isn't activation, candidate isn't evidence, and model success isn't publication authority**.

Our next experiments should be concrete and small: a pure reducer wrapping one low-risk KB publication, a three-fragment search document with a forced CDC rollback, and one UI page with three correlated but independent request traces. Compare operational failure recovery and developer investigation effort before expanding the machinery.
