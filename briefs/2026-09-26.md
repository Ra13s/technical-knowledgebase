# Run brief — 2026-09-26

The most useful result from this run is that several things we tend to phrase as “the agent should be careful” are actually **system-boundary guarantees**. A model cannot reason its way around missing authoritative state. If a mutating tool times out after the server committed, the client may genuinely not know whether retrying will duplicate the effect. If the only execution history lives inside the agent's writable workspace, the runtime being audited can also alter the evidence used to audit it. These are infrastructure problems, not prompt-quality problems.

That leads to a cleaner three-plane model for autonomous systems. The **reasoning plane** can remain probabilistic: planning, decomposition and adaptation belong there. The **effect plane** owns stable logical operation identity, retry semantics and authoritative outcome state. The **evidence plane** owns a trusted record of model/tool intent and actual executor outcomes outside the task workspace. This is a useful refinement of the existing deterministic-outer-loop idea because it tells us where specific guarantees should live instead of merely saying “keep critical things deterministic.”

The new idempotent side-effect pattern makes this very concrete. For every state-changing operation that may be retried, give the logical operation a stable idempotency key and expose a read-back/status operation that returns authoritative state. Reuse the same key across retry, resume and handoff; do not create new identities for the same logical write. More importantly, test fault classes explicitly: lost acknowledgement, late completion, duplicate delivery, partial batch and process restart. If correctness depends on the client inferring what happened from a timeout, the contract is still too weak.

The telemetry finding is the same structural lesson on the evidence side. The record used for production debugging or audit should be stored in a control-plane recorder that the task runtime cannot rewrite. Correlate model calls, tool requests and executor outcomes with stable run/operation IDs; keep recorder credentials outside the runtime; and prove that a completed run can be reconstructed from trusted telemetry alone. Monitoring can consume that evidence, but monitoring should not be confused with authorization or enforcement.

Spring AI TypeSafe Jev was the complementary optimization. Not every uncertain branch deserves another generative model call. If the desired output is a category, score, route or bounded judgement, a typed primitive can be easier to compose and test. The current library is early and hosted, so the right use is a labelled benchmark with confidence-based fallback to the current model path—not blind replacement based on vendor claims.

## What I would try next

Pick one internal mutating agent tool and inject lost-response, late-commit, redelivery and restart faults. The goal is to prove that repeated execution either returns the original outcome or converges safely without guessing. Separately, record one unattended run entirely through external telemetry and verify that you can reconstruct what actually happened without opening the agent's local session state.

For Jev, replace one low-entropy classifier/judge behind a confidence gate and compare calibration, latency and cost on labelled examples before deciding whether it belongs in the main path.
