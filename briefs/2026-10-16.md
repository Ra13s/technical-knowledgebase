# Run brief — 2026-10-16

Today the theme is **acceptance outside the model's comfort zone**. A coding agent can do the right programming work but violate the contribution process; a fast agent-generated UI experiment can pass its sandbox tests but still enter the production bundle; and a Java service can run perfectly while an observability upgrade makes its alerts incorrect. These aren't variations of one bug. They are different contracts, and each needs evidence from the authority that owns it.

The most consequential new agent research is **SWE-CC**, which evaluates functional patches against repository contribution rules. Its authors converted 823 policies across 12 repositories into deterministic checkers and ran 500 tasks through different coding-agent setups. They found that successful-looking contributions often violate policies, and nearly half the observed policy violations happen *during the run*. That's important: inspecting the final diff cannot reveal whether an agent skipped required steps or did something disallowed before producing clean output. We should represent rules as triggered checks with outcomes like pass/fail/not-triggered/withheld and consume tool events from the harness rather than believing the agent's self-report. The first place to try that is this very KB workflow.

**Meta Forum** offers a surprisingly practical production pattern for a different problem: let agents prototype aggressively, but compile experimental components into a separate app build instead of merely hiding them with a feature flag. Meta also exposed the live simulator's view hierarchy so agents could check which screen they were on, and ran repeatable navigation/stress scenarios with verification evidence attached to reviews. That combines three complementary properties: fast feedback, observable correctness, and an artifact-level boundary. None alone proves a feature is release-ready.

The strongest Java/platform primitive is the **OpenTelemetry Java agent 3.0 preview** in 2.32.0. New database and messaging conventions change attribute names, values, duration units and sometimes trace parent/link structure. Old and new fields can be emitted together for parts of the migration, but `/dup` is not a full compatibility mode. For a Spring service with JDBC and messaging, the safe path is to record baseline telemetry, opt into domain preview, validate dashboards/alerts and trace relationships, then enable the combined preview in staging. A passing integration test is not enough if the alert that should catch a future incident is now querying the wrong metric.

An independent comparison by Riptides also found credential-read gaps in several default coding-agent sandboxes. It strengthens our existing environment-containment lesson: protecting writes is different from protecting reads and inherited environments. A small canary-based negative-capability test could reveal dangerous assumptions without requiring a massive security programme.

We explored a promising niche engineering source, **Enola**, too. Its team used byte-identical semantic snapshots across real repositories to refactor a TypeScript extractor, then checked differential findings and performance. That's a useful experiment for any agent-assisted static-analysis change; it did not yet justify another canonical entry this run.
