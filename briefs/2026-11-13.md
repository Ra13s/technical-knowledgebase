# Run brief — 2026-11-13

A durable coding agent needs three different guarantees, not one convenient “memory” feature. It must be able to restore **the conversation protocol**, **the execution environment**, and **the ability to tell whether generated work is actually correct**. Each has a different failure mode, and fixing one does not fix the others.

**Conversation: Spring AI 2.1 makes model output an ordered event, not just text.** Signed thinking blocks, encrypted reasoning, tool-call inputs and results are sometimes required for the next model request. Dropping or reordering them can produce a hard API error or quietly discard reasoning continuity. The new ordered message parts and Session Memory's append-only turn log let a second Java service instance reconstruct the conversation from JDBC. The caveat is deliberate: the documentation currently describes RC2, not a stable 2.1 release. We have a clear prototype recipe, not a reason to rush every service off 2.0.x.

**Execution: Crab shows why restoring the chat is insufficient.** An agent may have installed tools, started a local server and modified uncommitted files. Crab uses an eBPF inspector and CRIU/ZFS checkpoints at agent-turn boundaries, distinguishing turns that affect no persistent state from those changing files or live processes. It reports a large benchmark reduction in checkpoint I/O with complete recovery on the evaluated tasks. But it is currently a root-owned, single-user Linux preview. A host-mounted worktree does not roll back, and a cloud-side write never rolls back. Our existing effect-claim/fencing gate still owns those actions.

**Correctness: TestSuiteBench makes a difficult gap measurable.** Researchers gave agents detailed specifications for 165 CLI applications and scored generated tests against independently chosen faulty versions. The best agent killed only about 55% of mutants, despite mostly valid tests. An agent can create software and generate tests that both look plausible while failing to detect basic contract violations. The practical Java/Spring pilot is to run PIT mutation testing on touched code and maintain a handful of known, requirement-specific bug variants, withheld from the candidate agent.

This run also turned up an independent Check Point exploit analysis of Cloudflare's workerd native glue. The flaw could be exploited from generated Code Mode in a self-hosted runtime, illustrating why one lightweight language isolate is not the same thing as an OS boundary. Cloudflare says its managed runtime is patched. We added that concrete boundary failure to the existing containment guide. Conversely, Hibernate 8.0's new graph-based flush coordinator was left as an RC experiment rather than prematurely recommended for production.

The best next experiment is a **two-worker agent recovery test plus a mutation-gated validation step**: persist an ordered session, checkpoint the sandbox, kill a worker, reconcile GitHub side effects, resume and demonstrate that the final test suite detects intentionally seeded defects. If any part is merely inferred from the model's closing message, the test has not established the guarantee.
