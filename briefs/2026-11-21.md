# Run brief — 2026-11-21

The best new engineering lesson is **reuse is only safe inside the right identity and version boundary**. Pulumi's newly announced infrastructure agents illustrate the operational side: a live incident can start an autonomous diagnosis and a PR, but a protected plan/policy gate and separate deployment credentials must own production writes. The agent's prompt is not what grants or removes authority, and connector credentials can accidentally bypass an attractive-looking role definition.

Spring AI **2.1.0 GA**, released on November 20, makes this sharply practical for Java. Its modern stateless MCP client can resolve tools per caller using PER_REQUEST, or maintain a carefully keyed CUSTOM per-user client. Sharing private tool lists or resolving callbacks once at startup can silently expose the wrong tools. The same release repairs a separate cross-user data path: Redis semantic caching now requires a trusted SemanticCacheScopeResolver so one user's private answer does not satisfy another user's semantically similar question. Blank scope must bypass caching; finite TTL and direct-cache API checks matter.

Airbnb's November 18 AirChat case study supplies the economic surprise. A model that looked approximately as cheap per task offline drove several-times-higher per-user production spend because it changed how frequently and how long engineers ran agents. Their gateway now combines frozen evals with requests and spend per user, four token classes and reasoning-effort ceilings. One newer model reduced the heavy-user group's spend to about a seventh at similar request volume. The numbers are first-party, but the *measurement distinction* is immediately reusable.

This intake adds three focused canonical recipes: [infrastructure incident-to-PR gates](../topics/ai/event-triggered-infrastructure-agent-pr-gates.md), [caller-scoped Spring AI modern MCP](../topics/spring/spring-ai-modern-mcp-client-scope.md) and [tenant-scoped Redis semantic caching](../topics/spring/spring-ai-semantic-cache-scope.md). It also updates the session/reasoning entry from 2.1 RC2 to GA, migrates the old TypeSafe-only decision guidance to core DecisionModel, and adds Airbnb evidence to agent-fleet economics.

The strongest experiment is a two-user Spring Boot 4.2/Spring AI 2.1 test harness: alternating callers, private MCP tool lists, semantic-cache collisions and credential revocation. A single wrong cross-user response or tool call must fail the build. Separately, a fake production incident should result in a previewed infrastructure PR but **never** a direct production apply.

A few items remain watchlist-only: GitHub's November 18 gh event listen needs Event Streams preview access; SpecGuardBench suggests generated validators can incorrectly reject spec-compliant alternative implementations; and Spring AI's proposed multi-agent graph project is not yet shipped.
