# KB intake — 2026-11-13

## Synthesis

This run exposed a distinction that is easy to lose when building “durable agents”: **there are at least three different states to preserve or verify, and none substitutes for the others.** One is the conversation's ordered protocol state, including signed/opaque model outputs and tool calls; another is the actual operating system state of the sandbox where code is edited and services run; the third is the behavioral contract that says whether the work is *correct*. Treating a transcript as complete recovery misses installed packages and processes. Restoring a container does not unwind external GitHub or database writes. And restoring both perfectly still does not make an inadequate test suite catch the errors an agent introduced.

The October 28 Spring AI engineering post and its 2.1 RC documentation give a concrete example of **protocol-exact conversational continuity**. Models increasingly return mixed sequences of reasoning, text, tool calls, tool results and opaque provider-specific signatures. Before message parts, a text-based session could reorder or drop those artifacts—sometimes yielding HTTP 400, sometimes silently degrading continuation. Spring AI 2.1's ordered `MessagePart` records and append-only Session Memory preserve complete turns and let a new instance resume from JDBC state. The important design choice is to persist faithful structured events, compact only at whole-turn boundaries and leave per-provider opaque data untouched. The trade-off is maturity: the official documentation is at RC2 as of this run, so this is a focused pilot, not a blanket upgrade recommendation.

The Crab paper and available OSS runtime reveal **OS-exact continuity** as a separate engineering problem. Their implementation correlates agent-turn boundaries with eBPF-observed filesystem/process changes, chooses the narrowest checkpoint granularity and overlaps snapshotting with LLM think time. It provides runnable recovery/rollback tests on Ubuntu with CRIU and ZFS. Crucially, the proof is bounded to the sandbox: host bind mounts are not checkpointed and external APIs are not rolled back. The work connects directly to our existing `durable-agent-tool-effects-and-fencing` pattern: external operations still need claimed identities, authoritative reconciliation and lease fencing. Crab reports strong benchmark recovery and I/O results, but its root-owned single-user daemon and unfinished daemon restart rehydration do not yet make it a production multi-tenant substrate.

The October 9 TestSuiteBench paper supplies a third, independently useful boundary: **behavioral correctness is not an intrinsic property of a passing generated test suite**. Across 165 specified applications, agents mostly wrote executable, reference-valid tests, yet even the best killed only around 55% of curated requirement-targeted faulty variants. The generalizable practice is to separate test validity from defect-detection strength, keep a hidden reference implementation/defect set, and evaluate requirements coverage as well as pass rate. For Java/Spring we can begin with PIT on changed packages, then add a small set of deliberately seeded *requirement-specific* bugs. Generic bytecode mutants are cheaper but not interchangeable with the carefully curated mutants used in the paper; score thresholds require local calibration.

A fresh independent security study reinforces the boundaries argument from another angle. Check Point found memory-corruption flaws in the native glue of self-hosted Cloudflare workerd; a prompt injection could steer generated Code Mode into a sandbox escape. Cloudflare patched the managed environment, and the end-to-end exploits were not run against production. For our KB the concrete change is to explicitly test and patch the runtime *beneath* generated code, and not treat “V8 isolate” as equivalent to OS-level separation for high-trust workloads. This improves the existing containment entry rather than creating another generic sandbox page. Meanwhile, Hibernate 8.0.CR1 and an AWS enterprise-agent reference model were explored but not promoted: one is still a release candidate needing compatibility evidence, the other mostly restates our existing outer-loop patterns.

~~~text
task + pinned spec
  -> ordered session/event log (reasoning/tool parts; no half turns)
  -> agent runs in checkpointable, isolated OS environment
  -> authoritative effect ledger for GitHub/cloud/database actions
  -> independent test validity + relevant defect/mutation detection
  -> CI/approval checked at exact head SHA
  -> publish and verify authoritative postcondition

Each boundary needs its own restore/check contract; no “agent completed” message proves all of them.
~~~

## New things we can use now

**[Mutant-gated agent-generated tests](../topics/testing/agent-generated-test-mutation-gates.md).** Freeze a trusted reference and versioned requirements, check a generated suite for validity *and* against independently seeded faults, and report surviving defect classes rather than counts of generated tests. Run TestSuiteBench with its official harness; start JVM adoption with a constrained PIT run plus hand-reviewed contract violations.

**[Agent sandbox checkpoint/restore at turn boundaries](../topics/ai/agent-sandbox-turn-checkpoint-restore.md).** A runnable Crab v0 Linux/CRIU/ZFS prototype demonstrates local OS recovery without replaying all agent steps. Specify checkpoint identity, failure gating, host-mount limitations and external-effect reconciliation explicitly.

**[Spring AI 2.1 ordered parts and JDBC Session Memory](../topics/spring/spring-ai-session-parts-replay.md).** Preserve provider-signed reasoning/tool-call sequences through streaming, compaction and worker restarts; use the new Session advisor and a caller-scoped session ID in an RC2 pilot, not as a GA migration commitment.

## Valuable agent-system designs discovered

**Crab (research + working OSS runtime):** coordinator intercepts agent-turn boundaries, eBPF inspector classifies net effects as none/FS/process/both, host engine multiplexes ZFS/CRIU savepoints and blocks model progression until the corresponding checkpoint is ready. Restore combines a process and filesystem version. The architecture is unusually concrete, but v0's root-owned single-user limitation means it belongs in isolated experiments, not uncontrolled agent hosting.

**Spring AI 2.1 Session Memory (reference implementation, RC):** append-only `SessionEvent` log, separately computed turn-aware view and compacted history, JDBC SPI and stateless ChatClient advisor frontends. Provider-specific signed/opaque payloads remain attached to ordered message parts. It is a practical session-control-plane architecture worth testing against tool-loop resume failures.

**TestSuiteBench (research/evaluation harness):** freeze human-readable specification, correct executable and curated mutants; give the candidate agent only the specification; measure valid tests separately from mutants killed. A hidden reference evaluator is also a useful design for *agent reviewers* because it avoids grading an agent by the tests it chose to write itself.

## Rejected / deferred

- **Hibernate ORM 8.0.0.CR1 (November 12):** graph-based flushing and `hibernate.flush.queue.type=legacy` are concrete and promising, but Jakarta Persistence 4.0/runtime compatibility and mixed DML/constraint behavior need a pinned pilot; do not declare a production migration on the basis of a release candidate.
- **AWS governed agent loop (November 12):** operationally reasonable service mapping, but it duplicates deterministic orchestration, scoped identity, telemetry and approval already in canonical KB.
- **Spotify Technology positioning (October):** shared agent/context runtime claims lack a novel end-to-end tool contract in this source.
- **Secondary agent testing percentages:** skip headline superiority claims from a third-party recap without locating and auditing the primary experimental method.
- **General-purpose sandbox rollback for GitHub actions:** explicitly rejected; local checkpointing cannot reverse off-host changes.

## Experiments worth trying

1. **Independent verifier for coding-agent tests.** Choose 15 Java/Spring defects with known historical fixes. Withhold reference fixes and custom mutants from the candidate agent. Compare self-written tests, an independent test writer and a validity+PIT+curated-mutant gate; count known bugs caught, false alarms, p95 CI time and review minutes.
2. **Crab crash matrix.** Use a disposable Ubuntu VM and the published no-key smoke test; then inject failure during read-only turns, file edits, live services and external API calls. Compare chat-only restart, full snapshots and semantic checkpoints on exact restored state, I/O and duplicated external effects. Add a host-bound-workdir case to prove the documented non-rollback.
3. **Spring AI session replay pilot.** On 2.1 RC2, persist one signed/opaque tool turn in JDBC and resume it through a second service instance. Test streaming, compaction at the 20-turn threshold, invalid provider signatures, cross-provider replay and session ownership.
4. **Generated-code runtime hardening.** Confirm self-hosted workerd versions are at or above the published fix; on high-risk workloads, exercise host/tenant isolation across native-extension faults in a separate VM/OS boundary.
