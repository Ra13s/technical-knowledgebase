# KB intake — 2026-09-26

## Synthesis

The strongest idea in this run is that several properties we casually ask an agent to "be careful about" are actually **system-boundary properties**. An authoritative execution record should not live only in the agent's mutable workspace. Retry safety for persistent writes should not depend on a model correctly inferring whether a timed-out request eventually completed. In both cases, the reusable move is to place the guarantee in infrastructure outside free-form reasoning: control-plane telemetry for evidence, and a stable tool/service contract for effects.

This sharpens the existing deterministic-outer-loop guidance into three planes. The **reasoning plane** can stay probabilistic and adaptive. The **effect plane** owns stable logical operation identity, retry semantics and authoritative outcome state. The **evidence plane** correlates model/tool intent with actual executor outcomes. A monitor can consume that evidence, but monitoring and enforcement should remain distinct responsibilities. Recent 2026 research on local agent traces and runtime monitoring is useful evidence for why these boundaries matter, while the exactly-once work makes the distributed-systems limitation especially concrete: there are fault states where the client simply does not have enough information to reason its way to a safe retry.

The Spring AI TypeSafe Jev finding is the complementary optimization. Not every uncertain decision deserves a full generative model. When the desired output is a branch, category, score or confidence threshold, a typed decision primitive can be easier to compose and test. Its current 0.1.0 maturity and hosted-service dependency mean we should benchmark and calibrate it on our own labelled workload rather than inherit vendor performance claims.

Anthropic's CI scaling write-up adds an operational consequence of agent adoption without requiring a new canonical page: faster code/review can move the bottleneck into the *freshness* of derived developer-infrastructure state. Their test-selection redesign separated stateless event ingestion from journaled state reduction. That reinforces the existing capacity-isolation rule that an agent trajectory consumes more than model quota; stale selectors and indexes are capacity failures too.

```text
model / agent
    |
    +------> control-plane telemetry ------> audit / evaluation
    |
    v
typed decisions / planning
    |
    v
tool gateway
  -> stable operation identity
  -> idempotency contract
  -> actual executor
  -> authoritative outcome
```

## New things we can use now

### Make agent side effects idempotent in the tool contract

New canonical entry: `topics/ai/idempotent-agent-tool-side-effects.md`.

For persistent mutations, provide a stable idempotency key and an authoritative status/read-back operation. Preserve the same logical key across retries and resumes. Do not let generic retry middleware blindly repeat a non-idempotent write after an ambiguous outcome.

The important distinction is between faults a read-back can resolve and faults such as late completion or transport redelivery where it cannot. The latter need service-side contract support rather than a better retry prompt.

### Externalize authoritative agent telemetry

New canonical entry: `topics/ai/external-authoritative-agent-telemetry.md`.

Keep the record used for production debugging/audit in a control-plane recorder separate from the task workspace. Correlate model calls, tool requests and actual executor outcomes with stable run IDs, keep recorder credentials outside the runtime, and test that completed runs can be reconstructed from trusted telemetry alone.

### Spring AI TypeSafe Jev for typed decision gates

New canonical entry: `topics/spring/spring-ai-typesafe-jev-decision-gates.md`.

Use `Noul`, `Choice` and `Score` when an AI component needs to return a typed judgement rather than prose. Compose thresholds in Java, route `INCONCLUSIVE` cases upward, bound self-refinement, and keep hard authorization/enforcement outside probabilistic judgement.

## Valuable agent-system designs discovered

**LIMBO's fault taxonomy:** a useful template for evaluating side-effecting agent tools. It separates unknown outcomes that can be resolved through authoritative read-back from late/in-flight/redelivery cases where a client lacks enough information. This tells us exactly where model reasoning ends and service contracts begin.

**External recording boundary:** recent agent trace-integrity work gives a simple architecture test: if the runtime being observed owns the only authoritative evidence store, the observability design is too weak for high-autonomy work.

**Anthropic test-selection redesign:** stateless listeners append events to external journal state; a separate consumer reduces that into queryable history. The useful lesson is not Anthropic's reported growth factor but the metric: track whether the state used for decisions is current, not merely whether requests return successfully.

## Rejected / deferred

**NovaFabric:** promising design for signed, portable and replayable run evidence, but its initial evaluation reports incomplete stream coverage and limited successful replay of tool-using workloads. Keep as an experiment candidate.

**Verifier trace-context study (arXiv:2609.28564):** useful evidence that auxiliary execution narrative can distort some automated verifiers, but the current evidence is specific to video-generation tasks and selected visual judges. No generic canonical rule yet beyond preferring independent primary evidence for verification.

**Kubernetes Node Readiness Controller:** actionable custom readiness/taint control with dry-run and bootstrap/continuous modes. Strong platform candidate, but still early and lower priority than this run's selected findings.

**Spring AI 2.1.0-M1 / Spring Cloud 2026.0.0-M1:** useful radar, but milestone APIs are expected to move. No canonical recipe until a specific capability clears the stability/actionability bar.

## Experiments worth trying

1. **Exactly-once tool test:** add a stable operation key to one state-changing internal agent tool and inject lost-response, late-completion, duplicate-delivery and restart scenarios.
2. **Telemetry reconstruction test:** capture one unattended agent workflow through a control-plane recorder and verify the run can be reconstructed without relying on local session state.
3. **Jev cascade:** replace one low-entropy chat-model classifier/judge with Jev 0.1.0, route low-confidence cases to the current path, and compare calibration, latency and cost on labelled examples.
4. **Derived-state freshness SLO:** add oldest-event age and state-version freshness to one CI/index/selector service rather than monitoring only queue depth and request success.
5. **Independent-verifier context test:** compare one automated evaluator with and without agent-authored narrative context while keeping primary evidence fixed.
