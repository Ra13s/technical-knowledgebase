# KB intake — 2026-09-12

## Synthesis

The strongest idea in this run is that mature coding-agent systems are becoming **resource schedulers for attention**. The expensive resource is no longer only model tokens; it is also deep reasoning, repository exploration, tool calls and developer trust. Uber attacks this from the economics side by measuring cost per accepted outcome and routing work to the cheapest model/harness that preserves quality. DoorDash and Wealthfront attack the same problem from code review: first decide *where* attention is needed, then gather bounded evidence, and only then spend strong-model reasoning on a candidate issue. The shared rule is: do not make a frontier model rediscover the whole world on every turn.

That changes how we should design agent harnesses. A useful default topology is now: cheap localization/search -> primary evidence -> strong judgement -> explicit falsification -> deterministic publication gate. Subagents are especially useful as search workers, but their summaries should not automatically become truth. Wealthfront's practice of discarding cheap-subagent conclusions while preserving the primary files they found is a clean mechanism for limiting error propagation. DoorDash adds the complementary rule that every candidate finding should survive an explicit disprove-it pass before a developer is interrupted. Cloudflare's 5,169-repository deployment shows that this style can be operated at high volume when the system is biased toward low finding counts and tracks bypasses as a product metric.

Uber adds a second missing piece to our existing harness guidance: **quality-preserving unit economics**. Instead of asking whether one model is cheaper, measure cost per merged PR, review, alert or cleanup at a required quality level. Break spend into turns, requests, tokens and model price; then attack waste where it appears. Static MCP schemas, chatty polling loops and overpowered subagent models are all measurable architecture costs. This also connects directly to our existing tool-search and programmatic-tool-calling entries: their value is not abstract elegance but fewer useless tokens and model turns while correctness remains measurable.

The non-agent finding reinforces the same boundary-first philosophy. Kubernetes 1.37's beta rootless node mode creates a realistic Kubernetes environment in a Linux user namespace, so local agents or integration tests can use a real cluster API without giving the node stack host-root. It does not remove the need for network/filesystem/credential controls, and CNI/CSI compatibility must be tested, but it gives us a concrete lower-privilege sandbox primitive for agent-driven Kubernetes work.

## New things we can use now

### Engineer agent fleets with outcome-denominated unit economics

New canonical entry: `topics/ai/agent-fleet-unit-economics.md`.

Use real historical tasks to benchmark model/harness configurations, track cost per useful outcome plus quality, route bounded subagents to cheaper models when they benchmark well, and treat context/tool plumbing as a measurable cost driver. Move deterministic polling/filtering loops out of the model loop and load tools on demand instead of paying repeated schema overhead.

### Rootless Kubernetes nodes for agent and test sandboxes

New canonical entry: `topics/platform/rootless-kubernetes-agent-sandbox.md`.

For Kubernetes 1.37+, test rootless kind/minikube as a lower-privilege environment for coding agents and integration tests. Verify `runningInUserNamespace`, record incompatible CNI/CSI/privileged workflows, and do not silently add host privileges back when something fails.

## Existing KB entries improved

### Precision-first multi-stage AI code review

Added five reusable mechanisms backed by independent production systems:

- scout/risk-localization before deep review;
- bounded research questions instead of generic "find relevant files" crawling;
- cheap subagents return primary evidence, not trusted conclusions;
- explicit disprove/falsification before posting;
- review-specific domain profiles built from repository rules, historical reviews, incidents and decisions.

The entry now also records DoorDash acceptance telemetry and Cloudflare break-glass/scale data as evidence, while explicitly warning not to copy their thresholds.

### Layered scoped agent memory with stateless reasoning sessions

Integral's 007 design strengthens the recommendation to use existing domain artifacts as handoff state. An investigator can write an issue, a fix agent can open a PR, a reviewer can request changes there, and the next agent can reconstruct state from the current artifact. This avoids inventing a second hidden coordination database when the issue/PR already is the durable workflow state.

## Valuable agent-system designs discovered

**Uber Software Factory:** the most reusable system-level design in this run. It combines benchmark-driven model routing, weaker default subagent models, explicit context limits, provider-aware prompt caching, dynamic tool loading, code-mode batching, graph-grounded context and live cost diagnostics. The important takeaway is not any one tuning value; it is that the whole fleet is operated with outcome metrics and real-work benchmarks.

**Wealthfront AI review:** a particularly strong pattern for multi-agent evidence gathering. A strong top-level reviewer asks bounded questions; cheaper research agents explore within budget; their prose answer is discarded and only primary sources/relevance information is retained for the final reviewer.

**Integral 007:** an intentionally boring stateless harness where external artifacts are the handoff state, role folders create conventions, `{role}-judge` adds a second-model quality gate, and full run traces can later be analyzed to improve prompts/harnesses.

## Experiments worth trying

1. **Agent cost dashboard:** for one internal coding/review workflow, add `cost per accepted outcome`, requests/turn, tokens/request, model, latency and retry rate. Compare at least two model routes on the same historical task set.
2. **Source-only research subagents:** change one reviewer/planner so cheap research workers return `{source, excerpt/location, relevance}` rather than a synthesized answer. Compare factual errors and cost against the current handoff.
3. **Disprove pass:** require candidate review findings to survive a dedicated counter-evidence search before publication; measure comments/PR and acceptance rate.
4. **Rootless cluster sandbox:** run an agent-driven Kubernetes integration suite against rootless kind and document exactly which CNI/CSI/privileged operations fail.
5. **Artifact-as-state pilot:** for one issue-to-PR workflow, remove hidden inter-agent state that duplicates the issue/PR and see whether retries/restarts become simpler without reducing correctness.
