## Synthesis

A useful common lesson from this run is that **scale does not remove authority; it exposes exactly where authority belongs**. The examples span a coding-agent runtime, Git's distributed storage system and Java TLS. In each case, the scalable or safer design reduces *implicit trust* instead of merely adding more AI or hardware. GitHub's new Copilot SDK server-to-server authentication gives background agents an organization-owned identity and short-lived installation token, separate from any developer session. Its per-reference Git storage design avoids one repository-wide write lock because updates to unrelated refs do not need to be ordered together. JDK 27's hybrid TLS 1.3 rollout makes modern cryptography available by default, but a Java upgrade is not proof that a connection negotiated the new key exchange. These are different technologies with a shared implementation discipline: **name the authority, make its scope minimal, then verify the actual effect**.

The most immediate coding-agent improvement is treating **identity, capability and permission triage as separate layers**. GitHub's 27 October public-preview server-to-server path allows an organization-installed GitHub App to make Copilot SDK requests without a signed-in user. The installation token expires in an hour; organization model and cost policies still apply, and Copilot inference permission is not repository write access. GitHub's 26 October Assisted permissions release addresses a different problem: too many approval interruptions. A model can classify *eligible* tool requests as safe, but a probabilistic permission assistant must sit behind enterprise/tool policy and must not substitute for mandatory authorization at the executor. Our existing enforcement-bound approval entry now makes that distinction explicit.

The most revealing distributed-systems case study is GitHub's **21 October** follow-up to its agent-scale Git infrastructure redesign. With five replicas spanning data centers and Azure, a repository-wide write lock and slowest-replica round trips limited the busiest repositories. GitHub is shifting coordination to individual refs, where ordering is actually required, and introducing an object-storage-backed virtual write replica plus independently scalable read replicas. It reports 3–4× higher throughput for disjoint ref writes in internal tests. That number is not a promised improvement for our services, and a hot `main` ref is still a hot ref. The transferable recipe is to isolate immutable payload writes from a versioned per-key metadata update, require durability before acknowledging success, and provide an authoritative or version-aware read path when a newly finished agent immediately reads its own result.

Java 27 shows how the same mindset applies to deployment verification. SunJSSE now defaults to offering `X25519MLKEM768` along with classical TLS 1.3 groups, improving resistance to harvest-now/decrypt-later attacks **when both peers negotiate the hybrid group**. A service behind Envoy or a load balancer may terminate TLS outside JSSE; explicit named-group overrides may discard the new default. Instead of treating the JDK upgrade as an abstract security achievement, the KB now has a rollout matrix for identifying TLS termination points, inspecting real handshakes, measuring compatibility and keeping an explicit fallback. This also shows why coding-agent metrics need care: the recent VeeReview study could not meet its own calibration threshold when measuring PR verification practice. Evaluators, like deploys, need an independent observable ground truth.

```text
unattended agent / service
  -> explicit workload identity (not a borrowed human session)
  -> bounded tool/OS capabilities + mandatory authorization
  -> independent per-key writes where invariants permit
  -> durable state + version/commit-bound evidence
  -> read back the authoritative outcome (not a model assertion)
  -> measure real safety, compatibility, latency and cost
```

## New things we can use now

**Copilot SDK workload-owned identity.** New [canonical recipe](../topics/ai/copilot-sdk-workload-identity.md): use the organization-scoped GitHub App installation token for an external Copilot SDK runner, or GitHub Actions' built-in `GITHUB_TOKEN` with `copilot-requests: write` for an organization-owned repository. Disable logged-in-user fallback; refresh hourly; keep repo writes under a *separate* identity and gate; trace app attribution and budget behavior. The org installation feature is a public preview and not directly an automation option for personal repositories.

**GitHub-inspired per-key write serialization.** New [production case study and prototype](../topics/platform/per-key-write-serialization-object-store-replicas.md): give independent refs/tasks independent CAS/ordered updates, place immutable content separately, acknowledge only durable state and specify an explicit minimum-version read path. A Postgres/object-store toy service and contention/fault matrix make the architecture testable without pretending to clone GitHub's infrastructure.

**JDK 27 hybrid TLS 1.3 rollout.** New [Java rollout guide](../topics/java/java-27-hybrid-tls-key-exchange.md): verify JSSE versus native/proxy termination, audit group overrides, inspect negotiated groups and test old/new peers before expanding the canary. JDK 27 has a default hybrid preference, but it does not guarantee all connections are post-quantum.

## Existing KB entries improved

**[Bind agent approvals to the exact side effect](../topics/ai/enforcement-bound-agent-approvals.md)** now distinguishes GitHub Copilot's Assisted permissions (model-assisted safety classification and fewer prompts) from mandatory, executable authorization at a trusted tool/side-effect boundary. This prevents a dangerous conflation of ergonomic permission automation with enterprise policy enforcement.

## Valuable agent-system designs discovered

- **GitHub App + Copilot SDK agent identity (2026-10-27):** organization installation, one-hour token, no human session, central model policy/spend, app-level cost attribution and independent GitHub mutation credentials. Unlike a personal token, this survives engineer turnover. Scope limitation: organizational Copilot entitlement, early preview, no per-app spending budget.
- **GitHub Git bridge (2026-10-21):** ref-scoped ordered writes instead of a repo lock; a durable object-storage participant that can coalesce disjoint writes; eventual/explicitly reconciled read replicas; a migration sequence that separates cloud relocation from changing storage semantics. It is a concrete high-load architecture rather than a claim every repository needs such complexity.
- **JetBrains Air's agent-agnostic workspace (2026 releases):** ACP-compatible agents in isolated workspaces with Java/Kotlin IDE intelligence and review, including Windows Docker task support. Useful corroboration of independent agents + repository-aware evidence, but most of that architecture is already represented in the KB; no new product-summary entry.
- **Independent test-evidence research:** VeeReview (October 21) found that its own PR-verification classification failed preregistered calibration, a useful warning against treating unvalidated LLM-as-judge metrics as ground truth.

## Rejected / deferred

- **VeeReview as a canonical verifier:** deferred. The study's 25-PR labeled reference had weak agreement; the authors report only 4–60% agreement against an 80% threshold on different build–verify pairs. It gives a strong experiment design and caution, not a ready-to-use reliable gate.
- **Large Java agent-testing observational study (October 26):** contextual evidence, but it reports associations, with no consistent coverage gain and important repository-level confounders. Do not prescribe “agent-authored tests are better” based on it.
- **JetBrains Air product updates:** concrete adoption path for ACP and worktrees, but already overlaps our canonical isolation, stable harness and semantic navigation recipes; revisit if a source-level measurable implementation difference emerges.
- **GitHub Copilot assisted permissions as standalone canonical topic:** would duplicate the existing approval guide and risk mistaking a convenience classifier for a security boundary. Incorporated the new primary evidence as a short update there instead.
- **Temporal product edition and general engineering trend posts:** interesting radar but no new distinctive implementable method beyond the existing durable agent effects and control-plane workflow entries.

## Experiments worth trying

1. **Workload identity drill:** for an organization with Copilot entitlements, compare GitHub Actions `GITHUB_TOKEN` inference with a GitHub App installation token in an external worker. Test explicit user-fallback disablement, expiry, org policy denial, budget exhaustion and CSV `app_client_id`. Verify the SDK identity cannot create a GitHub PR without a separately authorized publisher.
2. **Permission-assistant red-team evaluation:** replay 30 representative shell/file/URL requests through manual, assisted and deterministic-policy modes. Include manipulative tool arguments and privileged-but-benign-looking commands. Measure false approvals, human prompts and task success; mandatory protected-merge/deploy gates must remain invariant under assisted classification.
3. **Agent write-concurrency lab:** 100 independent refs versus one hot ref under a global lock and per-key CAS; inject blob-write/DB-commit crashes and stale reads. Measure throughput, p99 commit latency, stale read frequency, conflict retries, orphan objects and read-your-writes correctness.
4. **JDK 27 TLS compatibility canary:** test JDK 27-to-27, 27-to-older, native TLS proxy and mTLS paths. Verify negotiated hybrid versus classical group, failure rate and handshake overhead. The policy decision is whether and where to *prefer* hybrid, not an unmeasured claim about every encrypted connection.
5. **Verifier calibration:** take 25–50 internal Java PRs with actual tests and deployment context. Compare an LLM “verification quality” judge with two human raters and mechanical signals. Reject the judgement gate unless calibration reaches a team-defined threshold.
