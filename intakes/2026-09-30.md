# KB intake — 2026-09-30

## Synthesis

The strongest pattern in this run is **profile the work, then optimize the bottleneck — not the component that happens to be easiest to measure**. Cursor's production harness work shows that long-running agents accumulate surprisingly expensive static context: old prompt rules, rarely used tool schemas, unstable cache prefixes and verbose file reads. AgentPProf attacks the same problem from the observability side by aggregating many trajectories into semantic operation stacks, so the expensive thing becomes visible as “code exploration”, “test repair” or “tool setup” rather than a sea of individual spans. Augment reaches the workflow level: as coding got faster, it repeatedly looked for the next queue where work accumulated and automated that transition rather than assuming more code generation was still the constraint.

That gives us a concrete optimization loop for agent platforms:

```text
authoritative traces / outcomes
        |
        v
semantic cross-run profile + queue metrics
        |
        v
largest cost / latency / wait-state hotspot
        |
        v
one harness or workflow change
        |
        v
same workload / real-traffic A-B test
        |
        +---- quality regressed -> revert
        |
        +---- quality holds ----> keep, profile again
```

This changes how we should use the existing fleet-economics guidance. “Cost per accepted outcome” is the north-star metric, but it needs a profiler underneath it. Per-run tracing is enough to debug a failure; it is not enough to know what to remove from the harness or which SDLC transition to automate next. Cursor also adds a useful request-shape rule: keep the stable, frequently reused prefix small and cacheable; move variable setup later; progressively disclose low-frequency tools. Subagents are not automatically efficient either — fresh context can save tokens, but every context boundary introduces coordination and duplicate-work risk.

The Java and Kubernetes findings are narrower but pass the same admission test cleanly. JDK 27 can filter selected sensitive startup data inside JFR before supported events leave the JVM, with concrete runtime defaults and extension rules that can be canary-tested during an upgrade. Kubernetes 1.37 can now scale queue-backed HPA workloads to zero in core Kubernetes, but only when the wake signal survives zero Pods. Both replace a vague operational hope with an explicit platform contract that we can test.

Evidence strength differs across the run. Cursor and Augment provide production case studies but are vendor self-reports; Augment explicitly describes its 17,200-PR results as longitudinal rather than causal. AgentPProf is a research result with useful benchmark evidence, not a production guarantee. Oracle and Kubernetes sources define concrete current platform behavior and are the strongest basis for the Java/Kubernetes recipes.

## New things we can use now

### Profile agent fleets by semantic operation

New canonical entry: `topics/ai/semantic-agent-trajectory-profiling.md`.

Aggregate many sessions by task/skill/phase/action and weight the stacks by tokens, time, file effects or network/tool effects. Freeze the session corpus before comparing harness versions. Use traces for chronology and authoritative evidence; use semantic profiles to decide what to optimize.

### JDK 27 JFR in-process redaction

New canonical entry: `topics/java/java-27-jfr-in-process-redaction.md`.

Keep the JDK defaults, extend them carefully for organization-specific naming, and verify the result with harmless canary values in a real recording. The page records the event-coverage gaps so this is not mistaken for universal JFR sanitization.

### Scale queue-driven Kubernetes workloads to zero with HPA 1.37

New canonical entry: `topics/platform/kubernetes-hpa-scale-to-zero.md`.

Use `minReplicas: 0` only with Object/External metrics that remain observable at zero Pods. Verify `ScaledToZero`, treat the metrics adapter as a wake-up dependency, measure end-to-end cold start, and return workloads to at least one replica before disabling or downgrading the feature.

## Existing KB entries improved

### Agent fleet unit economics

`topics/ai/agent-fleet-unit-economics.md` now adds request-shape economics from Cursor's production harness work:

- remove obsolete model-era prompt scaffolding through A/B tests;
- keep only high-frequency/boot-critical tools in static context;
- move low-frequency tools behind progressive disclosure;
- keep cache-stable context before cache boundaries and variable setup after them;
- treat subagents as context isolation with a measurable coordination tax.

It also adds Augment's whole-system rule: queue growth is inventory. When code generation gets faster, measure where work waits next and optimize that transition rather than continuing to tune the already-fast stage.

## Valuable agent-system designs discovered

**Augment software factory:** four connected states — Requirements, Ticket, PR, Prod — with specialized agents on transitions, deterministic deployment after merge, and humans retaining product/architecture/production-risk judgment. The reusable pattern is: find the current queue, automate the mechanical part of that boundary, preserve consequential judgment, and measure the whole flow. Augment reports 17,200 merged PRs in its longitudinal analysis, with size-adjusted output rising 4.5x, median merge time falling 72%, and 14-day revert rate falling from 1.9% to 0.4%; the company explicitly says this does not isolate causality.

**Cursor harness efficiency:** a production example of treating the serialized request itself as infrastructure. Cursor trimmed roughly 66% of its system prompt, dynamically loaded low-frequency tools, restructured context for cache reuse and made subagent use less prescriptive. The company reports a 7% overall token-cost reduction without measured quality loss; exact gains are workload/provider-specific, but the experimental method is reusable.

**Auggie v2 harness:** a separate vendor example pointing in the same direction: narrower tool surface, semantic retrieval instead of exploratory turns, proactive compaction on a cheaper model, and a small extension-oriented core. The published benchmark is vendor-controlled, so it is evidence for the pattern rather than a transferable performance claim.

## Rejected / deferred

**OpenAI Agents API:** operationally important, but the current public-beta architecture — managed long-running harness, environments, subagents and resumable work — mostly reinforces existing deterministic-outer-loop, stable event/harness and telemetry entries. No new canonical page needed.

**Quarkus MCP 2.0.x stateless support:** useful concrete implementation evidence for the already-canonical MCP 2026-07-28 migration pattern. Its same-endpoint legacy/stateless support and official conformance testing strengthen that page, but do not justify a duplicate Quarkus-specific recipe yet.

**Scott Logic agentic-development business case:** sensible advice to measure cycle time, flow efficiency, deployment frequency and quality rather than AI activity. It lacks a sufficiently new implementation primitive relative to the existing fleet-economics and evidence-gate entries.

**Kubernetes 1.37 Memory QoS and newer DRA scheduling improvements:** both are useful radar items. HPA scale-to-zero won this run because it gives an immediately testable operational recipe with a clear workload boundary. Revisit the others when a concrete cgroup-v2 memory isolation or large-scale accelerator scheduling requirement appears.

## Experiments worth trying

1. **Semantic flamegraph:** freeze 50-100 completed coding-agent sessions, profile tokens and wall time, change one top hotspot and replay the same workload.
2. **Cache-shaped request A/B:** separate stable tools/instructions from variable environment/skill/subagent context and measure cache misses, cost, tool errors, latency and task success.
3. **Queue-as-inventory dashboard:** for one multi-agent workflow, graph oldest-item age and wait time at task, PR review, CI and verification boundaries; automate only the largest persistent queue.
4. **JFR canary-value gate:** during a JDK 27 upgrade, create a short recording with harmless marker values in startup configuration and verify the expected startup events contain the redacted marker.
5. **HPA zero-to-one drill:** let a queue worker reach zero, enqueue one canary job, and measure time from external metric change to first processing.
