# KB intake — 2026-11-17

## Synthesis

**The most important pattern this run is an independent evidence loop around increasingly autonomous software creation—not merely another agent working on the same task.** AWS's newly released Emulator is a striking example: the development workflow has a contract source (Smithy models), a reference authority (actual AWS behavior), agents that first construct and validate independent tests, separate agents that turn failed tests into reproducible issues, and narrowly scoped fixers that only get to ship through a distinct merge gate. The particularly reusable component is not “thousands of agents” but the **reference-validated fidelity corpus** and clear custody of evidence. A model cannot simply make a failing test disappear by changing its own oracle. This sharpens our prior [agent-generated test mutation gates](../topics/testing/agent-generated-test-mutation-gates.md) and [deterministic outer loop](../topics/ai/deterministic-outer-loop-agent-platform.md): independence matters at the *task contract*, *test generation*, *candidate patch* and *merge* boundaries.

Google's AQuA takes a complementary position **after deployment**. A task can be “complete” in the sense of HTTP 200, good latency and no tool error yet still violate a business requirement. Its ambient evaluator samples real production traces, drafts actual-versus-expected failures, clusters recurring mechanisms, independently verifies candidates from the original sessions, and then locates the suspected cause using the **code/prompt/tool snapshot that was actually deployed**. It does not have to edit the agent itself. Taken together, AWS and Google suggest a quality architecture spanning two timelines: pre-merge independent behavioral reference tests, followed by post-release sample/replay/verify/diagnose as real user workloads change. Offline coverage is a hypothesis about behavior; live evidence can reveal scenarios the gold set missed.

This is not evidence that every engineering team should launch an AWS-scale autonomous factory. AWS's throughput figures are first-party and its target is unusually well suited to reference testing because AWS itself can act as an oracle. Google's AQuA results are a small scripted replay, not demonstrated general-purpose production recall. The transfer-worthy idea is narrower: use multiple independent authorities, preserve the exact revision behind each observation, and measure *escaped behaviors and developer effort*, not just agent outputs. In applications without a reliable reference, we may need curated contracts, independent test authors and human acceptance rather than copying the automation topology.

AWS Emulator itself offers a practical engineering primitive separate from the agent-factory story: run real AWS SDK calls against isolated local HTTPS/SigV4 service instances in Java/Spring CI. Unlike an SDK mock, this can catch request serialization, validation and stateful integration failures cheaply. But it is **not real AWS**: unsupported operations return 501, coverage is graded by a growing fidelity suite, IAM and regional semantics are absent, and a Java test runner must trust a rotating local certificate. The correct gate therefore compares emulated operation coverage with a real-AWS sandbox for the flows that matter. This complements our Microcks contract-testing entry rather than replacing provider acceptance tests.

Finally, **the engineering runtime beneath the agent is part of the trust boundary**. Git's November 10 advisory patched six vulnerabilities, including malicious recursive clones reaching code execution and memory corruption in merge/patch code. An agent that checks out arbitrary repositories can trip those flaws even while perfectly obeying its own prompt. The existing Git conflict-staging recipe now specifies a patched Git binary (2.56.1+) instead of merely 2.56+. Uber's recent production security design adds another distinct boundary: an API operation may be authorized in isolation but inappropriate relative to the user's request. Intent/provenance checks can provide a calibrated semantic warning or veto; they **cannot override deterministic access controls, OS isolation or required human approval**. These are useful controls because they constrain a different failure class from fidelity tests.

~~~text
specification / known reference + scenario coverage
   -> independently validated conformance tests
   -> candidate implementation from bounded fixers
   -> exact-head test + policy + security merge gate
   -> deployed revision + structured tool/session telemetry
   -> sampled quality review + independent verification
   -> provenance-checked root cause at deployment SHA
   -> regression test / human triage / next bounded patch

Across every boundary: isolate credentials, preserve identity, and report unsupported or unverified outcomes explicitly.
~~~

## New things we can use now

**[Reference-oracle autonomous agent factory](../topics/ai/reference-oracle-autonomous-agent-factory.md).** AWS's three-team pattern is implementable for emulators, protocol replacements and compatibility migrations. Split reference-validation, issue discovery and repair into separate roles; store frozen oracle evidence; make each issue reproducible; bind fixes to one checkout and protected merge tests. An initial prototype should use 20–30 stateful/negative scenarios with hidden mutants, not aim for hundreds of concurrent agents.

**[Evidence-gated production agent quality outer loop](../topics/ai/production-agent-quality-outer-loop.md).** AQuA gives concrete `SAMPLE -> REVIEW -> CLUSTER -> VERIFY -> TRACK -> DIAGNOSE` stages, a domain goal file, shadow evaluation, protected telemetry and revision-pinned source citations. Its verifier should reject unsupported “issues”; an absent finding in a small sample should not imply that the defect is fixed.

**[AWS Emulator local SDK integration tests](../topics/platform/aws-emulator-local-integration-tests.md).** Use real AWS SDK v2 requests against a separate local emulator process per CI worker, with emulator-only credentials and pinned PKCS12 truststore for Java. Explicitly check `sts get-caller-identity`, per-operation fidelity scores and unsupported calls; escalate critical or unverified behavior to an isolated real-AWS staging test.

The semantic verifier is neither a permission source nor a sandbox.

## Valuable agent-system designs discovered

**AWS Emulator (first-party production engineering case).** Smithy models feed test writers with limited reference-AWS access; reference-passing scenarios enter a durable corpus; issue finders replay and cluster divergences; fixers operate on bounded tasks; compile, review, security and fidelity tests protect main. A remarkable whole-system design, but largely reproducible only when an independent and affordable reference can be queried. Its public GitHub repository supports architecture inspection; internal oracle/worker infrastructure remains private.

**Google AQuA (open-source recipe + scripted experiment).** A scheduled quality “sidecar” reads telemetry and deploy-time code snapshots, independently verifies clusters, and produces cited diagnoses without modifying production agents. Google's 32-session scripted test showed 42 raw findings, nine clusters, six verified; two prompt changes improved selected failure classes, but full-suite passes remained only 13/32. Use it as a debugging architecture, not proof that a model can reliably auto-grade itself.

**Uber (production security case).** Registered agent identities, personas and intents; action-time policy checks; prompt provenance and evidence chain; per-agent shadow/replay calibration; multiple narrowly tailored controls. This is a stronger composition than a single universal “safe/unsafe” classifier, but company claims are not independent effectiveness evidence.

## Rejected / deferred

- **AWS Emulator as a complete AWS compatibility guarantee:** rejected. A listed service with unsupported or unverified operations, missing IAM semantics and no regional variation cannot replace real provider acceptance tests.
- **Autonomous code creation without any human review for arbitrary products:** not generalized from AWS's specialized reference-oracle environment. Sensitive changes still need risk-weighted human/security gates.
- **Google AQuA as a reliable production failure-rate estimator:** sample selection, selective verifier inspection and small demo numbers do not justify that claim. Treat reported improvement as a scripted case study.
- **GitHub Agentic Workflows Safe Outputs:** already canonical; November coverage offered no sufficiently novel workflow contract.
- **Anthropic's November 18 code-review webinar listing:** future event at the time of this intake; wait for the actual technical content.
- **General Netflix data-ontology radar:** interesting architecture direction, but no verified new implementation contract from the scanned material this run.

## Experiments worth trying

1. **Small reference-oracle factory:** implement one 15-operation subset of a protocol emulator. Give writers an isolated real/reference endpoint, finders only frozen validated tests, and fixers one versioned issue/worktree. Keep a hidden 10-scenario/10-mutant holdout; compare regression escapes, issue duplication, accepted fixes per cost, and human audit minutes with a single general agent.
2. **Java/Spring AWS Emulator pilot:** take SQS and DynamoDB flows in one module. Compare Mockito, AWS Emulator SigV4/HTTPS tests, and an isolated AWS account for state transitions, invalid inputs, conditional-write errors and cleanup. Deliberately remove endpoint overrides and assert no genuine credentials/egress are available; fail on unknown fidelity rather than marking it as success.
3. **AQuA-style production-quality evaluator:** replay 200 sanitized Spring AI sessions with five seeded silent failures and benign lookalikes. Measure independently verified findings, source-citation validity, missed seeded defects, false blocks and per-session cost. Pair all diagnoses with an exact deployed config/source hash.
4. **Git binary and intent-policy hardening:** inventory `git --version` in CI runners, containers, IDE agents and hosting tools; upgrade to patched maintenance releases. Separately shadow-test Uber-style task-intent checks on 200 tool requests; never let semantic “allow” supersede authorization.
