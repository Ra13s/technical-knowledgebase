# KB intake — 2026-08-13

## New things we can use now

### Hibernate `@Immutable`

For Hibernate mappings that are intentionally read-only everywhere, annotate the entity with `org.hibernate.annotations.Immutable`. Hibernate then skips entity dirty checking/state snapshots and does not flush in-memory changes as updates. The canonical entry also records the different behavior for immutable collections and the fact that this is not database-level write protection.

Canonical entry: `topics/java/hibernate-immutable.md`

### Spring AI dynamic tool discovery

For Spring AI 2.0 agents with a large tool or MCP catalog, enable `ToolSearchToolCallingAdvisor` so tool definitions are discovered on demand rather than all being sent with every request. The entry contains the starter dependency, Boot properties, index choices and session-ID handling.

Canonical entry: `topics/spring/spring-ai-tool-search-advisor.md`

### Evidence before coding-agent changes

For issue-driven coding agents, require evidence that the reported problem still exists before changing production code, explicitly allow a verified **no-change** result, and require relevant code/tests/callers to be inspected before finalizing a fix. For higher autonomy, represent these requirements as structured runtime evidence rather than relying only on prose instructions.

Canonical entry: `topics/ai/evidence-gated-coding-agent-edits.md`

## Experiments worth trying

1. **Tool-search A/B:** register 20–50 realistic tools in a Spring AI test app. Compare the default advisor and tool-search advisor on prompt tokens, correct tool selection, latency and failure rate.
2. **Bug-fix evidence gate:** add the minimal evidence instruction to a coding-agent repository and feed it a mix of real bugs, stale/already-fixed issues and partially fixed issues. Measure unnecessary changes and missed real fixes.
3. **`@Immutable` smoke test:** mark one genuinely read-only reference entity immutable, mutate it in a transaction in an integration test, and verify Hibernate emits no `UPDATE`. This makes the silent-ignore caveat concrete for the team.
