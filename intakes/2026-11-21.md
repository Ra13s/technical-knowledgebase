# KB intake — 2026-11-21

## Synthesis

**The strongest lesson this run is that an agent's *request identity* determines the safe boundary for reusing context and performing actions—not the fact that two calls run in the same service.** Pulumi's new incident-response agents work from live infrastructure and alert context, but their valuable architectural distinction is between read-only diagnosis, a proposed versioned infrastructure change, deterministic IaC plan/policy checks, and deployment under different authority. Spring AI 2.1.0's modern MCP support reveals a subtler version of the same problem: if a multi-user application resolves downstream tools once at startup or shares a private tool-list cache, the resulting discovery and callbacks can end up bound to the wrong caller. Even a correctly authenticated Java app can become a confused deputy through the wrong *lifetime* of cached tool context.

**Spring AI's repaired Redis semantic-cache boundary makes this a data-security rule, not just a tools issue.** A semantically similar question from another user must not reuse the first user's private response; a similarity score says nothing about the second user's authorization. Spring AI 2.1 GA now requires an explicit SemanticCacheScopeResolver. Choose a scope from authenticated and entitlement-appropriate request context, bypass the cache when the scope is missing, use finite retention and test direct API paths. The modern MCP client similarly defaults to PER_REQUEST, with CUSTOM appropriate for a carefully maintained per-user client; SHARED is safe only when the underlying identity and tool listing really are shared. Both prevent a common failure mode: optimizing away the very identity boundary that the service was supposed to enforce.

**Airbnb's AirChat case study adds an important cost and evaluation counterweight.** Its offline coding-agent evals compared score and fully priced cost per task, yet a model that looked approximately equivalent in evaluation led to several-times-higher average spend per user in production. The model changed how engineers used agents: longer autonomous runs and more requests, dominated by repeated cached-context reads. A later model switch drastically reduced spend for the same heavy-user cohort. This argues that the outer loop must track **both quality per accepted task and observed behavior per active user**, and re-evaluate model/effort defaults after rollout, not merely before it. Evaluating a harness in a fixed sandbox and operating agents on real user demand are different experiments.

**One new mature feature and one new service design do not establish a universal recipe.** Spring AI 2.1.0 was released on November 20, with Boot 4.2 compatibility and critical fixes across GA and 2.0.3; this turns our 2.1 RC session-memory note into usable GA guidance and obsoletes the older TypeSafe-only integration entry in favor of the core DecisionModel API. Pulumi Agents/Delivery are a public preview and first-party product description, not controlled evidence that AI infrastructure remediation is safe. Connected-tool credentials can still have more privilege than intended even when a prompt says “read-only”. For the same reason a decision-model risk score should route to a human or stricter policy, never replace a deterministic deny rule.

The cross-source engineering rule is therefore **bind every reusable artifact to the authority and version that produced it**: an incident has a source event, environment and stack snapshot; a PR has a base/head revision and preview; an MCP tool list has a caller; a semantic cache answer has a trusted scope; an eval has a frozen task and cost model; a production report has an actual user/workload mix. Reuse is efficient only after these boundaries are correct. This extends the existing [deterministic outer loop](../topics/ai/deterministic-outer-loop-agent-platform.md), [identity-scoped gateway](../topics/ai/identity-scoped-mcp-gateway.md) and [agent-fleet economics](../topics/ai/agent-fleet-unit-economics.md) entries rather than contradicting them.

~~~text
observed alert / authenticated request / fixed eval task
    -> preserve exact event, principal, permission and version
    -> model may diagnose, route or propose
    -> tool list, cache hit and data access restricted to caller
    -> independent deterministic preview / policy / test gate
    -> PR and deployment under separate protected authority
    -> live telemetry: correctness, identity leaks, cost/user, outcomes
    -> re-evaluate and update only after verified evidence
~~~

Includes roles, run state, direct-apply prohibition, failure cases and a seeded-incident experiment. Based on Pulumi's 2026-11-18 preview system; do not turn product marketing into a safety claim.
- **[Spring AI modern MCP client scope](../topics/spring/spring-ai-modern-mcp-client-scope.md).** Use Spring AI 2.1 GA MODERN Streamable HTTP with PER_REQUEST or per-user CUSTOM scope, do not freeze callbacks at startup, propagate identity via transport context, and test private tool-cache isolation, revocation and WebFlux blocking behavior.
- **[Spring AI scoped Redis semantic cache](../topics/spring/spring-ai-semantic-cache-scope.md).** Patch to 2.1.0/2.0.3, require trusted SemanticCacheScopeResolver, bypass on null, use TTL, and test same-question different-tenant isolation and direct cache accesses. Addresses the cross-user disclosure/cache-poisoning class in CVE-2026-59417.

## Valuable agent-system designs discovered

**Pulumi Agents + Delivery (vendor deployment, November 18).** Integrates event triggers, runbooks, metric providers, Pulumi resource graphs and a team-owned agent role with PR-first infrastructure changes, deterministic deployment policy and approval stages. The transferable control points are independent credentials, resource-state-aware previews, change review and explicit separation of diagnosis from apply. Pulumi's reported rise to 40% agent-origin infrastructure operations is not a measurement of incident prevention or safe automated deployment.

**Airbnb AirChat/AirChat Remote (large internal operational deployment, November 18).** Interactive and isolated cloud agents route through a model gateway on Bedrock; seven fixed task suites score alternatives on the same prompts/graders at each effort, while per-user production metrics determine whether the choice remained cost-effective. A model's ability to support long autonomous sessions is itself a source of demand shifts and higher real spend.

**Spring AI 2.1 modern MCP (framework primitive, November 20).** A shared service can host both legacy and stateless MCP connections. Its runtime client-scope policy is a meaningful security/availability design choice, not merely a startup optimization; tool authorization remains the downstream server's job.

## Rejected / deferred

- **GitHub Event Streams / gh event listen:** promising event-driven replacement for PR polling (gh 2.105.0+), but preview and waitlist-only. Before adoption, test stream loss, reconnect, missed events, authoritative current state and idempotency. Do not represent it as generally available.
- **GitHub Copilot code review adaptive effort and secret finding:** interesting November 17 feature but risk-tiered review/secret scanning already live in canonical guidance; vendor announcement gives no neutral effectiveness study.
- **SpecGuardBench:** the paper finds agents can overfit test checks to reference implementations and reject spec-legal alternatives. Worth an acceptance-harness experiment, but the existing test-gate entry covers independent validation; avoid a second summary entry without a new verified recipe.
- **Spring Boot 4.0.10 and sampled general radar posts:** relevant routine maintenance/radar signals but not distinctive reusable implementation techniques from the portions checked.
- **Spring AI Agent multi-agent graphs:** announced roadmap for early December, not shipped; do not describe it as current GA functionality.
- **Pulumi usage growth and Airbnb cost reductions as causal efficacy guarantees:** both are first-party reports; neither by itself establishes safe autonomy or universally optimal model choice.

## Experiments worth trying

1. **Infrastructure alert -> reviewable PR with zero direct production writes.** Run 30 synthetic service alerts against one test Pulumi/Kubernetes stack, with a read-only agent identity and separate deploy principal. Include duplicate/forged alerts, bad runbooks, stale stack revisions, broad IAM edits and benign lookalikes. Assert zero unauthorized calls, deterministic plan diff checks and no automatic deploy. Record unnecessary PRs, correct fixes, minutes of human review and safe proposal latency.
2. **Two-user Spring AI isolation matrix.** In Boot 4.2 + Spring AI 2.1 GA, interleave two authenticated principals against a modern MCP ticket server with different tools and a Redis semantic cache with different private answers. Test PER_REQUEST vs intentionally unsafe SHARED, client custom-scoped revocation, blank cache scope, streaming, tool-list TTL, direct cache usage and a forged tenant header. Require zero cross-user disclosures and denial of unauthorized direct tool calls.
3. **Coding model rollouts: offline vs observed demand.** Freeze 50 representative tasks, score two models and several reasoning efforts for quality and four token-cost classes, then canary over real use with requests/user/week, accepted outcomes, p95 latency, spend/user/week and cache-read share. Revert or reconfigure when the same eval score induces materially different user behavior.
4. **Specification fidelity control.** Extend TestSuiteBench/PIT testing with two equivalent, spec-permitted implementations that differ from the reference code. Check whether an agent-generated validator accepts both and rejects deliberate requirement mutants; track false rejections as seriously as missed bugs.
