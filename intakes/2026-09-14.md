# KB intake — 2026-09-14

## Synthesis

The strongest idea in this run is that **agent capability is increasingly an interface-engineering problem**. A model is much more useful when important state, control and evidence are exposed as typed machine-addressable boundaries instead of forcing the model to rediscover them through pixels, prose or unstable implementation details. OpenAI's Codex App Server applies this at the harness boundary: one agent runtime owns threads, turns, tools, approvals and persistence while many clients consume a stable event protocol. Shopify applies the same principle inside the application: headless business logic plus Tardis/CLI controls let agents inspect state, navigate and validate behavior without spending most of the loop poking at a simulator.

The implication is broader than "give the agent more tools." Good agent tools expose **authoritative state at the abstraction level where correctness can be checked**. If the fact we care about is the analytics event emitted after checkout, expose the event stream; do not ask a vision model to infer it from a screenshot. If the fact is whether a long-running coding task is still active, keep durable thread state in the harness; do not make the browser tab the database. If the fact is whether the model request contract changed, sign the full request and fail a stale VCR cassette rather than replaying an old answer by filename.

This also sharpens our existing evidence-gate guidance. Shopify's River shows that evidence is not only typed; it is **versioned**. A green CI result belongs to a particular head SHA. A ledger entry is a claim that must be reconciled against live repository/PR/tracker state. A merged PR is still not closure until the default branch and authoritative downstream state confirm the intended postcondition. Vectors VCR reaches the same rule from testing: playback is trustworthy only while the request signature still matches. In both cases, evidence without identity/freshness is stale context wearing a suit.

A useful architecture emerging from these sources is:

```text
        authoritative runtime / repo / app state
                         |
                         v
             typed control + event boundary
                         |
                         v
                      agent
                         |
                         v
                proposed action/change
                         |
                         v
       evidence bound to exact artifact/version
          (request signature / SHA / checkpoint)
                         |
                         v
             deterministic publish gate
                         |
                         v
          verify authoritative postcondition
```

The design rule for future agent systems is therefore: before adding another reasoning layer, ask whether the agent is still wasting intelligence reconstructing state the software could expose directly. A five-line `inspect state` command can be worth more than a much larger model if it removes minutes of ambiguous observation from every iteration.

## New things we can use now

### Expose one agent harness through a stable event protocol

New canonical entry: `topics/ai/stable-agent-harness-event-protocol.md`.

When one harness needs IDE, CLI, desktop, web or remote clients, keep thread/turn/item lifecycle and durable state in the server/runtime and expose a versioned bidirectional protocol. Translate unstable internal events into a small stable external schema, negotiate capabilities, generate bindings, and let the server initiate approval requests. Use MCP or a simple SDK/CLI instead when the richer lifecycle is unnecessary.

### Build agent-addressable application feedback loops

New canonical entry: `topics/ai/agent-addressable-application-feedback-loop.md`.

For UI-heavy work, separate domain behavior from rendering and expose typed `inspect` / `navigate` / `act` controls plus structured events. Use those controls to reach known states quickly, then validate the real UI for visual/accessibility/performance properties. For migrations, compare stable event/state/checkpoint behavior across implementations and explicitly ignore known nondeterminism rather than relying on manual parity review.

### Record/replay AI model calls with request-signed cassettes

New canonical entry: `topics/testing/ai-model-vcr-record-replay-tests.md`.

This promotes the Vectors VCR candidate recorded on 2026-09-12. Record real Spring AI/LangChain4j interactions during deliberate fixture creation, then run normal CI in strict playback. The cassette signature should include the complete material request contract so prompt/tool/options changes fail as stale. Keep live model evals separate: playback proves our integration can handle a known interaction, not that today's model remains good.

## Existing KB entries improved

### Evidence-gated coding-agent edits

Shopify River adds the missing lifecycle after "tests passed": bind verification to the exact head SHA, invalidate CI after rebase/force-push, reconcile agent ledgers with live state before resuming, and verify the default branch plus authoritative tracker/dependency state after merge. The entry now treats `fixed`, `superseded/already fixed`, `rejected with evidence`, and `escalated with evidence` as valid outcomes instead of optimizing for patch production.

It also adds a useful handoff rule: when human judgement is genuinely required, preserve the evidence and ask the owner the **smallest unresolved question** needed to continue rather than throwing the whole investigation back over the wall.

## Valuable agent-system designs discovered

**Codex App Server:** a strong example of separating the agent harness from all presentation surfaces. The server owns durable threads and translates internal core events into typed lifecycle events; clients can reconnect, stream progress, render diffs and answer server-initiated approval requests without reimplementing the agent loop.

**Shopify Helix + Tardis:** perhaps the most practically interesting design this run. Helix breaks migrations into small provable checkpoints with tests, visual review, adversarial review and human approval; Tardis gives agents structured access to live app state/events and commands. Shopify also binds plan acceptance to a content hash so a modified plan cannot inherit stale approval.

**Shopify River:** useful because it focuses on the transitions around a patch rather than generation. It checks claims against current repository state, refuses to overwrite human-owned branches, throws away stale CI after head changes, hands off narrow decisions, and only declares closure when authoritative systems agree.

## Rejected / deferred

**Java 26 HTTP/3 `HttpClient`:** this passes the actionable test (`HttpClient.Version.HTTP_3`, `HttpOption.H3_DISCOVERY`, explicit fallback/discovery modes), but it is deferred to keep canonical output focused. It remains a good future Java networking entry when a concrete project needs HTTP/3 or when Java 26 adoption makes the decision more common.

**MCP logging in Spring AI:** useful current implementation detail, but the MCP 2026-07-28 specification already deprecated the logging feature. The durable guidance is already in the MCP upgrade entry: migrate protocol-version boundaries deliberately. For new stdio servers, keep diagnostics off stdout; use stderr and OpenTelemetry rather than canonizing a deprecated capability.

**Shopify security scanning harness:** excellent production evidence for partitioned context, real test oracles, deterministic scripts and model-independent harness design, but those mechanisms already map to existing search/evidence/deterministic-outer-loop entries. No new page is needed just because the case study is impressive.

## Experiments worth trying

1. **Harness protocol extraction:** take one internal agent that currently couples UI/runner/runtime and expose only `thread`, `turn`, typed `item` events and one approval request over local JSONL. Build a second tiny client against it and see whether agent behavior stays identical.
2. **Agent-addressable UI pilot:** give one UI workflow a debug-only semantic control surface (`inspect`, `navigate`, `act`) and measure edit-to-verified-feedback time against the current screenshot/manual loop.
3. **VCR testing lane:** convert 5-10 live-provider Spring AI/LangChain4j tests to request-signed record/replay fixtures with strict playback in CI; deliberately mutate one prompt/tool schema and verify the fixture becomes stale.
4. **SHA-bound evidence gate:** attach `head_sha` to build/test/static-analysis evidence in one coding-agent workflow and automatically invalidate prior results after any repair/rebase commit.
5. **Post-merge closure check:** for one cleanup/security workflow, keep the task open until default-branch state and the external tracker/control plane both confirm the postcondition rather than closing on merge alone.
