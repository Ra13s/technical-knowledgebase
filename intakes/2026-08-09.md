## Scope

Initial seed run. The repository had no prior canonical knowledge or processed-source ledger. Baeldung Java Weekly #658 was used as a discovery source and its strongest linked material was followed into primary/deeper articles.

## What is genuinely new / worth retaining

### Agentic development is becoming a systems problem

The strongest cross-source theme is that faster code generation moves the bottleneck into task decomposition, context, verification, integration and human attention. Better agent workflows therefore need executable feedback and architectural boundaries rather than simply more concurrent model calls.

### Modularity now has machine-consumption economics

Refactoring can reduce the amount of repository context an agent needs even when total code volume changes little. This creates a new measurable dimension of technical debt: unnecessary context surface.

### Virtual Threads move the bottleneck

JDK 24 removes a major adoption barrier, but cheap threads expose downstream capacity limits more directly. Thread pools should no longer be mistaken for the system's intended backpressure mechanism.

### Control planes should preserve running systems

Reconciliation and static stability are useful general architecture principles beyond cloud-provider internals. Desired state and observed state should be explicit, and existing workloads should avoid synchronous control-plane dependency where possible.

## What strengthened existing understanding

- Semantic program tooling (IntelliJ/LSP) appears increasingly important for coding agents.
- Explicit goal/action/state abstractions in Embabel and Jakarta Agentic AI suggest agent orchestration is beginning to become normal application architecture rather than bespoke prompt loops.
- AI-assisted migrations reinforce that confidence must come from tests, traceability and specifications, not subjective inspection of large quantities of generated code.

## Contradictions / tensions

No strong direct contradiction was found in this seed set. The main tension is between increasing agent autonomy and the growing verification burden. The likely resolution is not permanently heavy human supervision, but increasingly automated confidence mechanisms.

## Practical implications

1. Make repositories easy for both humans and agents to navigate and validate.
2. Treat modularity as an AI-development productivity concern.
3. For blocking Java services, test Virtual Threads before choosing reactive programming purely for concurrency scalability.
4. Explicitly identify downstream resource limits whenever application-level concurrency becomes cheaper.
5. Use reconciliation/static-stability questions when designing orchestration and platform services.

## Experiments worth running

- Measure verified throughput at several parallel coding-agent counts.
- Measure agent token/context cost before and after modularizing an oversized component.
- Compare text-only versus semantic/LSP navigation for the same coding task.
- Run a Spring MVC service on Virtual Threads and observe database/downstream saturation under load rather than only request-thread metrics.
