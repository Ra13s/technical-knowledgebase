# Intake — 2026-09-06

## Synthesis

The strongest pattern in this run is that a good agent system increasingly looks less like a clever prompt and more like a **controlled search/reasoning component embedded inside ordinary software architecture**. The model is allowed to explore, synthesize and revise; durable memory, correctness, budgets, lifecycle and side effects remain explicit state owned by the surrounding system.

Three independent systems illuminate different parts of that boundary. Anthropic's long-running harness work shows that agent scaffolding itself is perishable: context resets, planners and evaluator passes can be load-bearing for one model generation and needless overhead for the next. Meta's KernelEvolve shows the opposite case, where extra harness structure is genuinely valuable because the task has a hard objective function: let the LLM explore many implementations while a deterministic evaluator rejects incorrect code and measures performance. Coinbase's CEEcil shows that continuity should not mean keeping an immortal chat session alive; durable knowledge can live outside the model, be consolidated and retrieved selectively, while each reasoning invocation starts from fresh live state.

Together they suggest a more precise default architecture for serious agents:

```text
durable task state / memory / constraints
                |
                v
        model reasoning or search
                |
                v
      deterministic evaluation
                |
       evidence / pass / fail
                v
 deterministic lifecycle + budgets
                |
      publish / review / side effect
```

This sharpens several existing KB rules. "Deterministic outer loop" is not only about tests after generation; mandatory lifecycle behavior should also live in deterministic hooks around the model loop. "Use more agents" is not a standing architecture rule either: planners, reviewers, resets and fan-out should earn their place through ablation against real tasks whenever models change. And "give the model more context" is not the same as memory: long-lived organizational knowledge needs provenance, freshness, retention and retrieval policy that survive model sessions.

The practical consequence is to design harness components as replaceable modules with an explicit reason for existing. Use deterministic evaluators aggressively where correctness or fitness can actually be measured; externalize durable state; and periodically delete scaffolding that no longer buys measurable reliability. Safety boundaries are the exception: sandboxing, permissions, approvals and audit controls exist because the model is untrusted, not because today's model happens to be weak, so they do not get ablated away after a good benchmark run.

## New things we can use now

### Ablate coding-agent harness scaffolding when models change

Treat planners, context resets, evaluator passes, decomposition and similar non-safety layers as hypotheses about model limitations. On meaningful model upgrades, remove one component at a time against a stable real-task eval set and keep it only if it materially improves quality or human effort relative to its latency/cost.

Canonical entry: [`Ablate coding-agent harness scaffolding when models change`](../topics/ai/ablate-agent-harness-scaffolding.md)

### Search-based code optimization agents with hard fitness gates

For tasks with a reliable executable oracle and objective fitness, use the LLM as a candidate generator inside bounded search. Correctness is a hard gate; benchmark/profile results and diagnostics guide the next candidates; the outer system owns selection, budgets and termination. Meta KernelEvolve demonstrates this production shape for hardware kernels, but the pattern generalizes to bounded SQL/query, algorithm, serialization and configuration optimization problems.

Canonical entry: [`Search-based code optimization agents with hard fitness gates`](../topics/ai/search-based-code-optimization-agents.md)

### Layered scoped agent memory with stateless reasoning sessions

Keep durable team knowledge outside the conversational context. Scope observation before ingestion, retain raw observations briefly, consolidate useful decisions/outcomes, retrieve relevant memory on demand, expose provenance/freshness, and rebuild each reasoning invocation from current live state. Keep workers, publishing, dedupe, spend caps and kill switches in a deterministic service boundary.

Canonical entry: [`Layered scoped agent memory with stateless reasoning sessions`](../topics/ai/layered-scoped-agent-memory.md)

## Existing KB entries improved

### Deterministic outer loop for coding-agent platforms

Open SWE adds a useful implementation detail to the existing Dropbox Nova-derived pattern: lifecycle guarantees belong in middleware/backstop hooks around the agent loop. Examples include draining queued follow-up messages before a model turn, converting tool failures into structured evidence, preserving stable task/thread identity, and opening/updating a PR after work only through the surrounding publication policy.

## Valuable agent-system designs discovered

- **Open SWE** is useful less as a new canonical architecture than as independent convergence evidence. Stripe, Ramp and Coinbase internal agents are described as arriving at the same family of primitives: workflow-native invocation, isolated sandboxes, curated tools and subagents. Its deterministic middleware provides concrete implementation examples for our existing outer-loop rule.
- **Coinbase CEEcil** is a particularly strong whole-system case study because memory is only one piece: it separates a deterministic Go service (ingest, state, workers, publishing, dedupe, audit, kill switches) from probabilistic reasoning. That is the same boundary already emerging from our approval and outer-loop entries, now applied to a persistent team agent.
- **Coinbase Mux** provides additional production evidence for one-worktree/branch/terminal-per-agent concurrency, but the reusable isolation pattern is already canonical, so another page would add duplication rather than knowledge.

## Rejected / deferred

- **Spotify — Coding Is No Longer the Constraint**: strong evidence that standardized codebases and platform investment matter more as generation volume rises, but this run did not yield a sufficiently specific new implementation recipe beyond existing developer-platform/agent guidance.
- **Cobalt browser-flow recordings**: asking an agent to return playable video evidence of a reproduced bug or tested fix is concrete and potentially useful. It remains an experiment candidate because the current evidence is a vendor feature announcement rather than a demonstrated cross-tool verification pattern.

## Experiments worth trying

1. On the next primary coding-model upgrade, replay 20–50 recent agent tasks and ablate one expensive harness component at a time. Track task success, escaped defects, human correction time, latency and cost.
2. Pick one measurable performance hotspot and compare one-shot optimization against a bounded search agent with reference tests, profiler diagnostics and a fixed candidate/cost budget.
3. Prototype scoped team memory for one opt-in engineering stream: short-lived observations → daily consolidated summary → Git-versioned durable knowledge → on-demand retrieval into fresh reasoning sessions. Measure repeated re-briefing, stale answers and retrieval misses.
4. Add deterministic `before_model`, tool-error and `after_agent` hooks to one existing coding-agent workflow so follow-up routing, failure normalization and publication are enforced outside the prompt.
