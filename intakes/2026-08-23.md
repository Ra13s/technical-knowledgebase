## New things we can use now

### Renovate can regenerate Gradle verification metadata in the dependency PR

If Gradle dependency verification is enabled, dependency bumps intentionally fail until the new artifact is represented in `verification-metadata.xml`. Renovate `postUpgradeTasks` can run Gradle's `--write-verification-metadata` before committing the update, so the dependency and verification metadata are reviewed together.

Canonical entry: [`Renovate + Gradle dependency verification metadata`](../topics/platform/renovate-gradle-verification-metadata.md)

### Coding agents that alter Maven builds should inspect the resolved build, not just `pom.xml`

A repeatable four-command review catches transitive dependencies, inherited/effective POM changes, settings/mirrors and plugin dependencies:

```bash
mvn dependency:tree
mvn help:effective-pom
mvn help:effective-settings
mvn dependency:resolve-plugins
```

Canonical entry: [`Review AI-generated Maven build changes`](../topics/ai/review-ai-generated-maven-build-changes.md)

## Existing KB entry improved

### Hibernate `@Immutable`

Expanded the existing entry with a concrete JSON/custom-value performance case:

- entity-level `@Immutable` does not necessarily remove the Java value type's deep-copy/cache serialization cost;
- use `@Mutability(Immutability.class)` on JSON/custom basic fields only when code replaces the reference rather than mutating it in place;
- for truly immutable L2-cached entities, `@Cache(READ_ONLY)` is an appropriate strategy candidate;
- profile for `deepCopy`, dirty-checking and JSON serialization before applying the optimization.

The published benchmark is treated as workload-specific evidence, not a promised speedup.
