# Intake — 2026-08-29

## New things we can use now

### Spring Boot 4.1 can enforce outbound address policy after DNS resolution

`InetAddressFilter` is a first-class Spring Boot 4.1 HTTP-client primitive for SSRF defense. A global bean can restrict Spring-managed outbound clients to external addresses; per-client `HttpClientSettings` can enforce narrower CIDR policies. The practical default for URL-fetching code is now: add an address filter and test loopback/private rejection instead of relying on hostname validation alone.

Canonical entry: [`Spring Boot outbound SSRF mitigation with InetAddressFilter`](../topics/spring/spring-boot-inetaddressfilter-ssrf.md)

### Use the same API contract to generate consumer mocks and provider conformance tests

Microcks' Testcontainers module can import an OpenAPI/AsyncAPI artifact in JUnit, expose mocks from its examples, and then run the same contract against a real implementation. This is a concrete way to reduce drift between handwritten mocks, documentation and provider behavior.

Canonical entry: [`Microcks Testcontainers contract testing`](../topics/testing/microcks-testcontainers-contract-tests.md)

### Mandatory agent approval belongs at the side-effect enforcement point

A model/harness confirmation is bypassable if another path can call the tool/API. For consequential side effects, bind approval to the exact operation, arguments, target, requester/agent identity, expiry and replay state; revalidate those values immediately before execution. MCP MRTR can carry the pause/resume lifecycle, but its `requestState` must be integrity-protected and does not replace the authorization control plane.

Canonical entry: [`Bind agent approvals to the exact side effect`](../topics/ai/enforcement-bound-agent-approvals.md)

## Experiments worth trying

1. On a Spring Boot 4.1 service that accepts remote URLs, add `InetAddressFilter.externalAddresses()` and integration tests for loopback, RFC1918 and an allowed public destination.
2. Take one existing OpenAPI contract and replace a handwritten dependency mock with a Microcks Testcontainer; then run a provider conformance test from the same artifact in CI.
3. For one side-effecting agent tool, move approval enforcement from the harness into the tool/API boundary and verify that changing any approved argument forces a new approval.
