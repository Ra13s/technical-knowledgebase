# Intake — 2026-09-02

## New things we can use now

### Hibernate ORM 7.4 core `@Audited`

Hibernate 7.4 now has an incubating core `org.hibernate.annotations.Audited` model for current-state + audit-log tables. The practical part is not “auditing exists”; it is that historical state can be read through ordinary Hibernate sessions/HQL, and a standard Envers schema can be migrated without a default-schema rewrite.

Decision rule: evaluate core `@Audited` for new Hibernate 7.4+ audit requirements or when Envers' separate query model is a real pain point; do not migrate a working Envers setup merely because the new API exists, because core auditing is still incubating.

Canonical entry: [`Hibernate ORM 7.4 core @Audited`](../topics/java/hibernate-core-audited.md)

### Spring AI HyDE query transformation

For RAG where users describe symptoms or business concepts while the documentation uses specialist terminology, generate a short hypothetical answer-like passage and use **that only as the vector-search query**. Spring AI's `QueryTransformer` plugs directly into `RetrievalAugmentationAdvisor` and composes with conversation compression.

The guardrail is important: the hypothetical passage is retrieval bait, not evidence. Final generation remains grounded in the real retrieved documents.

Canonical entry: [`Spring AI HyDE query transformation`](../topics/spring/spring-ai-hyde-retrieval.md)

## Existing KB entry improved

### Evidence-gated coding-agent edits

DoorDash's stale-feature-flag cleanup provides a useful production-strength extension to our existing evidence gate:

- when source code is not the source of truth, fetch authoritative runtime/control-plane state before editing;
- insert the human checkpoint before mutation when that state is ambiguous;
- isolate parallel coding agents in independent git worktrees;
- make PR creation conditional on deterministic build/test/coverage/static-analysis gates rather than the model declaring success.

Their flag-cleanup workflow uses live rollout state to prevent hardcoding the wrong value, then runs each confirmed cleanup in an isolated worktree with a hard timeout and validation gates.

## Rejected / deferred

- **LinkedIn multi-agent AI code review** — strong production evidence for independent parallel reviewers, dedup/cross-validation and pairwise pre-ship evals. It is actionable, but it is a larger reviewer architecture rather than a small primitive; keep it as an experiment candidate until we have a concrete code-review harness to apply it to.
- **DoorDash centralized MCP Agent Gateway** — also highly actionable, especially centralized credential injection, per-agent/user authorization and curated task-oriented tool bundles. It is a platform-sized pattern and overlaps our existing approval/tool-disclosure guidance, so it was not added as another broad architecture page in this run.
- **JDK release/security cadence and other release news** — useful operational awareness, but no new reusable implementation recipe was identified for canonical knowledge.

## Experiments worth trying

1. Build a 20–50 query RAG retrieval set containing conversational questions that currently miss known relevant chunks; compare raw vector search vs HyDE on hit@k, answer groundedness, p95 latency and cost.
2. Spike Hibernate 7.4 core `@Audited` on a disposable schema, including a `@Changelog` entity and an `atChangeset()` historical query. If migrating Envers is relevant, verify the existing `REVINFO`/audit tables are read without DDL changes before considering adoption.
3. Add a generic `external_truth` pre-edit gate plus disposable-worktree + deterministic submission gates to a maintenance-agent harness. Verify that ambiguous runtime state produces an abstain/approval request rather than a speculative patch.
4. For AI code review, A/B one independent second reviewer only on high-risk PRs and measure unique valid findings vs added token/latency cost before considering a full multi-agent reviewer.
