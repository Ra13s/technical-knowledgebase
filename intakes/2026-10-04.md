# KB intake — 2026-10-04

## Synthesis

The strongest pattern in this run is **separate adaptive behavior from the infrastructure that defines what is real**. Replit's current harness work gives the core model more freedom to decide when and how to delegate, while the harness still defines the available specialist roles and cost/effort choices. Uber's large MCP deployment points in the same direction: broad discovery can remain flexible while platform state stays explicit.

The Java finding is the measurement version of that rule. If the request scheduler shares the system-under-test JVM, a GC pause can stop the benchmark driver too. The test then misses arrivals during the pause and can understate tail latency. Running the driver in another JVM puts the observer in a different pause domain, which is a concrete methodology improvement for p99/p99.9 work.

Kubernetes 1.37 Memory QoS adds another practical distinction: **feature enabled does not mean behavior enabled**. The Beta feature gate is on by default, but throttling and tiered reservation remain inactive unless the corresponding kubelet fields are configured. That changes the rollout procedure immediately: canary explicit settings and measure the workload effects rather than assuming an upgrade changed memory behavior.

The agent sources strengthen existing KB guidance rather than requiring another generic page. Replit suggests treating routing policy as scaffolding to re-test after model changes; Uber provides production-scale evidence for progressive tool discovery; and a source-level study of eleven coding harnesses shows production harnesses converging around explicit, configurable subsystems.
