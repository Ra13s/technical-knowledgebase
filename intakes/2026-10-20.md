# KB intake — 2026-10-20

## Synthesis

This run makes the boundary between **agent reasoning and durable, verifiable effects** more concrete. The strongest source was Temporal's experiment making the Pi coding agent recover across worker crashes. A tool call is not safely retryable just because the worker disappeared: a Git push, PR creation or external request can succeed after a claim was recorded but before its result reached the transcript. The workable protocol is to persist a claim before invocation, reuse a saved result, report an unsaved result as *unknown*, and read the authoritative outside state before trying again. Meanwhile a fencing lease prevents an old worker from publishing stale transcript state. This is the failure-handling counterpart to our existing idempotent side-effect and deterministic outer-loop patterns.

Two production agent teams independently push orchestration *away* from free-form model decisions. Kong runs review agents inside shared GitHub Actions workflows with a separate controller, sandbox and model gateway; after discovering duplicated exploration by multiple reviewer agents, it moved model/skill/effort routing to deterministic triage. Meta's Thin Orchestrator similarly uses a fixed seven-step protocol around specialist agents and composable workflow templates. The shared architecture is a small authoritative coordinator that knows the current state, permissions, budget and route, alongside model-powered specialists that only know the domain and scoped inputs. This is not an argument against specialized agents; it is a reason to avoid paying LLMs to rediscover stable workflow structure.

Naresh Jain's Java API/Kafka experiment adds a necessary counterweight: executable feedback can make a cheaper model much more reliable, but may waste substantial time and money on a model that already consistently meets the same hidden acceptance tests. The right harness is therefore **task- and model-dependent**. Keep independent final verification mandatory; selectively spend inner-loop contract guidance and evaluation tokens where measured acceptance improves. The research on multilingual safety guards also warns that even a faithful translation of a user request can change a guard's allow/block decision while the tool call itself stays byte-identical. Guard quality is a measurable property of the real languages and tasks, not just an English prompt.

Outside coding agents, StackAI's document-indexing case study shows the same durability principle in a more general pipeline. Split download, parse, chunk and index into individually recoverable stages; cache expensive parser results by content **and settings**; use durable waits and authenticated callbacks for asynchronous parsers; pass blob references rather than documents through workflow history. The contrast is useful: for file ingestion most failed stages can be retried with stable idempotency keys, whereas arbitrary coding-agent tool effects may have **unknown outcomes** and require reconciliation first. We should encode that difference explicitly in our tool contracts instead of pretending all retries are equal.

~~~text
trigger + fixed source state
  -> deterministic triage / workflow template
  -> scoped agent or pipeline stage
  -> claim or idempotency key before external effect
  -> durable result / unknown-outcome reconciliation
  -> independent acceptance checks
  -> authoritative publication + outcome metrics
~~~

## Valuable agent-system designs discovered

**Temporal / Pi (prototype, published October 8):** durable session JSONL and workspace Git bundles beside a Temporal Workflow, Activities for model/tool calls, a per-call claim-before-effect record, ordered step sealing and lease-guarded transcript appends. The chaos demo kills workers repeatedly, but doesn't establish exactly-once behavior for arbitrary external APIs.

**Kong KSAI (production case study, October 16):** one pinned reusable GitHub Actions workflow per repo, central event/identity and spend control, model routing, bubblewrap sandbox with carefully scoped credentials, deterministic review triage, structured findings and developer approval boundaries. Kong reports a 37% decline in median review cost after its triage change. This is a promising design to prototype in one repository; it is not independent evidence of fewer escaped bugs.

**Meta Thin Orchestrator (production case study, October 19):** 14 reusable domain agents, more than 20 workflow templates, and a small router following no-op checks, required-input gathering, auto-discovery, reliability gates, scoped delegation and publication. Knowledge files are loaded on demand, not embedded into a gigantic orchestrator prompt. Meta reports column configuration work dropping from days to less than an hour, without a controlled comparison.

## Experiments worth trying

1. **GitHub publication crash matrix:** on an isolated test repo simulate an agent crash just before PR creation, after the PR was created but before receiving its response, and after merge. Resume from external PR/ref state, proving no duplicate PRs or unsafe blind retries.
2. **One-repo KSAI-style reviewer:** move triage into a deterministic CI step with an explicit budget and isolated reviewer identity. Compare one reviewer and targeted specialist review on 30–50 frozen PRs; measure valid severe findings, noise and cost per accepted finding.
3. **Contract-feedback ablation:** on Java/Spring HTTP + Kafka tasks run two model classes with and without OpenAPI/AsyncAPI feedback; always keep independent hidden acceptance tests and record total repair cost.
4. **Document-ingestion chaos test:** ingest 200 synthetic mixed-size files; kill extractors, duplicate webhooks and update documents mid-run. Assert deduplicated parsing, correct newest index version and bounded retry expense.
5. **Multilingual safety guard pairs:** hold tool calls and context constant, translate only the trusted user instruction (including Estonian) and compare allow/block changes against each guard's natural rerun variance.
